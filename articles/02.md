## 1. ROS 2 系統連通與除錯 ★★★

### 題 1-1：統一 ROS_DOMAIN_ID（去年 5 分，幾乎送分）

**症狀：** judge 只看得到 feeder，看不到板子：

```text
[p1_judge]: visible ROS nodes, count=1, nodes=['p1_feeder']
```

**解法步驟：**

1. 查 PC 端的 domain：`echo $ROS_DOMAIN_ID`（沒有輸出就是 0）。
2. 查板子程式：`grep -rn "domain" src/client/`，找到 `int ros_domain_id = 1;`。
3. **改板子端**，讓它和 judge 一樣。judge 不能改，CI 上的環境你也改不到：

```cpp
int ros_domain_id = 0;   // 和 judge / feeder 相同
```

4. 重新燒錄 → 開 agent → reset 板子 → `ros2 node list` 應該同時看到兩個 node。

```text
[p1_judge]: visible ROS nodes, count=2, nodes=['ebnn_mnist_client', 'p1_feeder']
```

> 如果題目說「judge 在 domain X」，就把板子設成 X。若 PC 端也要改，記得**每個終端機**都要 `export ROS_DOMAIN_ID=X`，然後執行 `ros2 daemon stop`。

### 題 1-2：只能用 CLI 找出系統的錯誤

**可能的埋雷方式：** topic 名稱打錯、namespace、型別不同、QoS 不相容、node 沒有 spin。

**解法：** 照 `01_ROS2操作指南.md` 第 3 節的順序查。考前一定要把 `practice/ros2/bug_hunt/bugs.py` 的 6 個情境都練過一次。

**考場上可以先存一份「系統快照」**，之後慢慢看：

```bash
{ for n in $(ros2 node list); do echo "=== $n"; ros2 node info $n; done
  for t in $(ros2 topic list); do echo "=== $t"; ros2 topic info -v $t; done
} > ~/snapshot.txt 2>&1
less ~/snapshot.txt
```

### 題 1-3：用 CLI 回答問題（例如「某 topic 的型別、頻率、資料流向」）

| 問題 | 指令 |
|---|---|
| 有哪些 node？ | `ros2 node list` |
| 某 node 收什麼、送什麼？ | `ros2 node info /xxx` |
| topic 的型別？ | `ros2 topic list -t` 或 `ros2 topic type /xxx` |
| 型別有哪些欄位？ | `ros2 interface show <型別>` |
| 發佈頻率？ | `ros2 topic hz /xxx`（等 5 秒以上讀 average rate） |
| 資料內容？ | `ros2 topic echo /xxx --once` |
| 誰在收、誰在送、QoS？ | `ros2 topic info -v /xxx` |
| 畫出資料流 | 依 `node info` 的 Subscribers / Publishers 連成箭頭 |

### 題 1-4：實作 feeder（定時發佈資料）

**範本：** `practice/ros2/feeder_template.py`（已用假 rclpy 測過邏輯）。

**要點：**

1. 速率從設定讀：去年是 `load_config().publisher["p1"]` → `create_timer(1.0 / rate, self.tick)`。
2. **先等訂閱者連上再開始送**：`if self.pub.get_subscription_count() == 0: return`。不然前幾筆會在 discovery 完成前遺失。
3. 每筆都要帶 **id**（judge 用 id 對答案）。
4. numpy 影像轉訊息欄位：`msg.data = img.flatten().tolist()`。
5. 送完 `self.timer.cancel()`。

去年 p1 的完整解答在 [第 7.1 節](#71-去年-p1feeder--mnist_callback)。

### 題 1-5：實作 processor（訂閱 → 計算 → 發佈）

**範本：** `practice/ros2/processor_template.py`。把演算法寫進 `compute()`；如果訊息有 id，**輸出一定要帶回同一個 id**。

### 題 1-6：多板分流與吞吐量最佳化 ★★★

**方法 A：固定速率輪流分配**（`practice/ros2/multi_feeder_template.py`）

```python
pub = self.pubs[self.idx % len(self.pubs)]   # 第 i 筆送給第 i % N 塊板子
```

**方法 B：閉迴路流量控制**（`practice/ros2/flow_feeder_template.py`，**推薦**）

- feeder 同時訂閱輸出 topic，每塊板子最多 `WINDOW` 筆在處理中，收到結果才補送下一筆。
- 速度會自動貼近板子的極限，也不會塞爆佇列。快的板子自動分到比較多筆。
- 有逾時機制：某筆遲遲沒有結果就釋放名額，系統不會卡死。
- 已用模擬測試驗證：兩塊速度不同的板子，加上 5% 的結果遺失，仍能全部跑完。

**調速率的程序（兩種方法都適用）：**

```text
1. 先用保守速率（例如 5 張/秒）確認「全部正確」。
2. 每次把速率提高約 1.5 倍，記錄：收到幾筆、正確幾筆、總時間。
3. 正確數開始掉到門檻附近（去年是 40/50）時，退回前一個速率。
4. 計分只看「達門檻後的速度」，所以最佳點是「剛好還在門檻之上的最快速率」。
```

### 題 1-7：吞吐量的瓶頸在哪裡

```text
總時間 ≈ max(傳輸時間, 運算時間) × 筆數 ÷ 板子數（流水線順暢時）
```

| 瓶頸 | 怎麼判斷 | 怎麼改善 |
|---|---|---|
| 序列埠傳輸（最常見） | 訊息很大（例如 784 bytes 的影像）；115200 鮑率下每 byte 約 87 µs | 減少傳輸量（打包、壓縮）、提高鮑率（若允許）、多板 |
| 板子運算 | 量 callback 的執行時間 | 演算法最佳化、查表、組語、另一顆核心、DMA |
| feeder 速率 | `ros2 topic hz` 輸入端遠低於板子能力 | 提高速率 |
| 掉資料 | 收到筆數 < 送出筆數 | 降速、加大 QoS depth、改用閉迴路 |
| Python 端 | 每筆都 print、在 callback 裡做很多事 | 拿掉 print、預先轉好所有訊息 |

**預先轉好訊息**（避免在 timer 裡花時間轉 numpy）：

```python
self.msgs = [self.make_msg(i, img) for i, img in enumerate(images)]   # __init__ 裡先做完
def tick(self):
    self.pub.publish(self.msgs[self.idx]); self.idx += 1
```

## 2. micro-ROS 板子端程式 ★★★

### 題 2-1：補完 subscription callback 並發佈結果

**通用解法（ESP32 / Pico 都一樣）：**

```cpp
// 全域：輸出訊息放在全域，避免每次 callback 都重新初始化
custom_msgs__msg__Result out_msg;          // ← 依題目的型別

void input_callback(const void *msgin) {
  const auto *in = static_cast<const custom_msgs__msg__Input *>(msgin);
  // 1. 讀輸入（欄位名稱以 ros2 interface show 為準）
  // 2. 計算
  out_msg.id = in->id;                     // 3. id 一定要帶回去
  out_msg.value = compute(in);
  rc_check_soft(rcl_publish(&result_pub, &out_msg, NULL));   // 4. 發佈
}
```

**C 語言的型別名稱規則**：`套件__msg__型別`，例如 `custom_msgs/msg/MnistImage` → `custom_msgs__msg__MnistImage`，標頭檔是 `#include <custom_msgs/msg/mnist_image.h>`（駝峰改成底線小寫）。

### 題 2-2：不定長陣列的記憶體配置（不做就收不到，而且不會報錯）

```cpp
// 輸入：Vertex[] vertices（不定長）
#define MAX_V 128
static custom_msgs__msg__QsortVertex in_buf[MAX_V], out_buf[MAX_V];

void setup() {
  // ... 其他初始化 ...
  in_msg.vertices.data = in_buf;   in_msg.vertices.capacity = MAX_V;  in_msg.vertices.size = 0;
  out_msg.vertices.data = out_buf; out_msg.vertices.capacity = MAX_V; out_msg.vertices.size = 0;
}
```

- `ros2 interface show` 顯示 `uint8[784] data` 是**固定長**，不用配置；顯示 `uint8[] data` 是**不定長**，一定要配置。
- 訊息裡有 `string` 也一樣要配置（`.data`、`.capacity`、`.size`）。

### 題 2-3：多加一個 subscription / timer

```cpp
rclc_executor_init(&executor, &support.context, 2, &allocator);   // ← 1 改成 2
rclc_executor_add_subscription(&executor, &sub_a, &msg_a, &cb_a, ON_NEW_DATA);
rclc_executor_add_timer(&executor, &timer);
```

### 題 2-4：板子端加速

| 方法 | 說明 |
|---|---|
| 縮短 `spin_some` 的 timeout | `RCL_MS_TO_NS(100)` 改成 `RCL_MS_TO_NS(1)`，讓迴圈更常檢查新資料 |
| callback 裡不要 `malloc` / `delay` | buffer 一律宣告成 `static` 全域 |
| 能在 `setup()` 先算的就先算 | 例如 CRC 表、常數表 |
| 減少要傳的位元組 | 看訊息欄位是不定長才有辦法縮短（例如影像二值化後打包成 bit） |
| 改用另一顆核心算 | 見 [第 5.3 節](#題-5-3core0-負責收發core1-負責計算) |
| 浮點轉換 | 影像 `uint8 → float` 用 `x * (1.0f / 255.0f)`，乘法比除法快 |

### 題 2-5：Pico (RP2350) + micro-ROS 的完整骨架

```c
#include "pico/stdlib.h"
#include "pico/multicore.h"
#include "pico/util/queue.h"
#include <rcl/rcl.h>
#include <rclc/rclc.h>
#include <rclc/executor.h>
#include <rmw_microros/rmw_microros.h>
#include <std_msgs/msg/int32.h>
#include "pico_uart_transports.h"

typedef struct { int32_t value; } job_t;
static queue_t job_q, res_q;
static rcl_publisher_t pub;
static rcl_subscription_t sub;
static std_msgs__msg__Int32 in_msg, out_msg;

static int32_t compute(int32_t v) { return v * 2; }        // ← 題目的演算法

static void core1_main(void) {                              // core1：只負責計算
    job_t j;
    while (true) {
        queue_remove_blocking(&job_q, &j);
        j.value = compute(j.value);
        queue_add_blocking(&res_q, &j);
    }
}

static void sub_cb(const void *msgin) {                     // core0：收到就丟給 core1
    const std_msgs__msg__Int32 *m = (const std_msgs__msg__Int32 *)msgin;
    job_t j = { .value = m->data };
    queue_add_blocking(&job_q, &j);
}

int main(void) {
    rmw_uros_set_custom_transport(true, NULL,
        pico_serial_transport_open, pico_serial_transport_close,
        pico_serial_transport_write, pico_serial_transport_read);
    gpio_init(PICO_DEFAULT_LED_PIN);                        // Pico 2 W 沒有這個定義（LED 接在無線晶片上）
    gpio_set_dir(PICO_DEFAULT_LED_PIN, GPIO_OUT);

    queue_init(&job_q, sizeof(job_t), 32);                  // 要在 launch core1 之前
    queue_init(&res_q, sizeof(job_t), 32);
    multicore_launch_core1(core1_main);

    rcl_allocator_t allocator = rcl_get_default_allocator();
    if (rmw_uros_ping_agent(1000, 120) != RCL_RET_OK) return 1;   // 最多等 agent 2 分鐘

    rclc_support_t support;
    rcl_init_options_t opts = rcl_get_zero_initialized_init_options();
    rcl_init_options_init(&opts, allocator);
    rcl_init_options_set_domain_id(&opts, 0);                      // ← Domain ID
    rclc_support_init_with_options(&support, 0, NULL, &opts, &allocator);

    rcl_node_t node;
    rclc_node_init_default(&node, "pico_node", "", &support);
    rclc_subscription_init_default(&sub, &node, ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Int32), "/number");
    rclc_publisher_init_default(&pub, &node, ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Int32), "/double");

    rclc_executor_t executor;
    rclc_executor_init(&executor, &support.context, 1, &allocator);
    rclc_executor_add_subscription(&executor, &sub, &in_msg, &sub_cb, ON_NEW_DATA);

    gpio_put(PICO_DEFAULT_LED_PIN, 1);                            // LED 亮 = 連上 agent
    while (true) {
        rclc_executor_spin_some(&executor, RCL_MS_TO_NS(1));
        job_t r;
        while (queue_try_remove(&res_q, &r)) {                    // rcl_publish 只在 core0 呼叫
            out_msg.data = r.value;
            rcl_publish(&pub, &out_msg, NULL);
        }
    }
}
```

**重點：** micro-ROS 的函式**只能在 core0 呼叫**（它不是執行緒安全的），core1 只做計算，兩邊用 `queue_t` 交換資料。

## 3. 位元運算與 RISC-V 組合語言 ★★

已驗證的參考實作：`practice/c/bitwise.c`（20 萬組隨機值比對通過）。

### 題 3-1：C 語言位元操作

| 要做的事 | C | RISC-V（基本指令） | RISC-V（RP2350 擴充） |
|---|---|---|---|
| 只留低 4 位 | `x & 0x0F` | `andi a0, a0, 15` | |
| 低 4 位設 1 | `x \| 0x0F` | `ori a0, a0, 15` | |
| 低 8 位反相 | `x ^ 0xFF` | `xori a0, a0, 255` | |
| 全部反相 | `~x` | `not a0, a0` | |
| 左移 / 右移 4 | `x << 4` / `x >> 4` | `slli` / `srli`（有號數用 `srai`） | |
| 設定第 n 位 | `x \| (1u << n)` | `li t0,1; sll t0,t0,a1; or a0,a0,t0` | `bset a0, a0, a1` |
| 清除第 n 位 | `x & ~(1u << n)` | `...; not t0,t0; and a0,a0,t0` | `bclr a0, a0, a1` |
| 反轉第 n 位 | `x ^ (1u << n)` | `...; xor a0,a0,t0` | `binv a0, a0, a1` |
| 測試第 n 位 | `(x >> n) & 1` | `srl a0,a0,a1; andi a0,a0,1` | `bext a0, a0, a1` |
| 取 bits 7..4 | `(x >> 4) & 0xF` | `srli a0,a0,4; andi a0,a0,15` | |
| 組合兩個 byte | `(hi << 8) \| lo` | `slli a0,a0,8; or a0,a0,a1` | `packh a0, a1, a0` |
| 數 1 的個數 | 見 `bitwise.c` | 迴圈 | `cpop a0, a0` |
| 位元組反轉（換 endian） | `bswap32()` | 多條 shift/and/or | `rev8 a0, a0` |
| 32 位元整體反轉 | `bitrev32()` | 多條指令 | `rev8 a0, a0` + `brev8 a0, a0` |
| 旋轉 | `(x << n) \| (x >> (32 - n))` | `sll + srl + or` | `rol` / `ror` / `rori` |
| 前導零 / 尾端零 | 迴圈 | 迴圈 | `clz` / `ctz` |
| 最低位的 1 | `x & -x` | `neg t0,a0; and a0,a0,t0` | |
| 是否 2 的冪次 | `x && !(x & (x - 1))` | | |

> pico-sdk 編 RISC-V 時預設的 `-march=rv32imac_zicsr_zifencei_zba_zbb_zbs_zbkb` 已經包含 Zbb / Zbs / Zbkb，所以上表右欄的指令可以直接用。

### 題 3-2：用 RISC-V 組語實作函式

**寫法 1：inline asm（寫在 .c 裡）**

```c
static inline uint32_t bits_7_4(uint32_t x) {
    uint32_t r;
    __asm__ ("srli %0, %1, 4\n\t"
             "andi %0, %0, 15"
             : "=r"(r)          // 輸出：%0
             : "r"(x));         // 輸入：%1
    return r;
}

static inline uint32_t popcount_hw(uint32_t x) {        // Zbb：一條指令
    uint32_t r;
    __asm__ ("cpop %0, %1" : "=r"(r) : "r"(x));
    return r;
}

static inline uint32_t popcount_loop(uint32_t x) {      // 基本指令版（Kernighan）
    uint32_t cnt, tmp;
    __asm__ volatile (
        "li   %0, 0\n"
        "1:\n\t"
        "beqz %2, 2f\n\t"
        "addi %1, %2, -1\n\t"
        "and  %2, %2, %1\n\t"
        "addi %0, %0, 1\n\t"
        "j    1b\n"
        "2:"
        : "=&r"(cnt), "=&r"(tmp), "+r"(x));   // =& 早期覆寫、+ 讀寫
    return cnt;
}
```

**寫法 2：獨立的 `.S` 檔**（加進 CMake 的 `add_executable(app main.c funcs.S)`）

```asm
    .section .text
    .globl  crc32_asm
    .type   crc32_asm, @function
# uint32_t crc32_asm(const uint8_t *buf, uint32_t len)   a0 = buf, a1 = len
crc32_asm:
    li    t0, -1                # crc = 0xFFFFFFFF
    li    t3, 0xEDB88320        # 反轉多項式（li 會自動展開成 lui + addi）
    beqz  a1, 3f
1:  lbu   t1, 0(a0)             # 讀 1 byte（無號）
    xor   t0, t0, t1
    li    t2, 8
2:  andi  t4, t0, 1             # 取最低位
    srli  t0, t0, 1
    neg   t4, t4                # 0 → 0，1 → 0xFFFFFFFF（當遮罩）
    and   t4, t4, t3
    xor   t0, t0, t4
    addi  t2, t2, -1
    bnez  t2, 2b
    addi  a0, a0, 1
    addi  a1, a1, -1
    bnez  a1, 1b
3:  not   a0, t0                # 回傳 ~crc
    ret
    .size   crc32_asm, .-crc32_asm

    .globl  bitrev32_asm
    .type   bitrev32_asm, @function
bitrev32_asm:                   # uint32_t bitrev32_asm(uint32_t x)
    rev8   a0, a0               # [Zbb]  反轉 4 個 byte 的順序
    brev8  a0, a0               # [Zbkb] 反轉每個 byte 內的 8 個 bit
    ret
    .size   bitrev32_asm, .-bitrev32_asm
```

C 端宣告：`extern uint32_t crc32_asm(const uint8_t *buf, uint32_t len);`

### RISC-V 呼叫慣例（寫 .S 一定要遵守）

| 暫存器 | ABI 名稱 | 用途 | 函式內可以直接改嗎？ |
|---|---|---|---|
| x10–x17 | `a0`–`a7` | 參數；`a0`（`a1`）是回傳值 | 可以 |
| x5–x7, x28–x31 | `t0`–`t6` | 暫存 | 可以 |
| x8–x9, x18–x27 | `s0`–`s11` | 要保留 | **不行**：要先存到 stack，用完再還原 |
| x1 | `ra` | 返回位址 | 呼叫別的函式前要先存起來 |
| x2 | `sp` | 堆疊指標 | 保持 16 bytes 對齊 |
| x0 | `zero` | 永遠是 0 | — |

### 常見錯誤

1. **立即值超過範圍**：`andi/ori/xori/addi` 的立即值只有 12 bits 有號（−2048 ~ 2047）。`andi a0, a0, 0xFFF` 會出錯，要先 `li t0, 0xFFF` 再 `and a0, a0, t0`。
2. **`lw` 讀非對齊位址**：pico-sdk 的 RISC-V 編譯有 `-mstrict-align`，非對齊的 32 位元存取不可靠。從 byte 陣列組 word 要用 `lbu` 逐一讀取，或用 C 的 `load_le32()`。
3. **inline asm 的輸出比輸入先寫入**：要用 `"=&r"`（early clobber），不然編譯器可能讓輸出和輸入共用同一個暫存器。
4. **在 .S 裡用了 `s` 暫存器卻沒保存**：呼叫你的 C 程式會壞掉，而且很難查。
5. **有號 / 無號**：右移有號數用 `srai`、無號數用 `srli`；載入 byte 時 `lb` 會符號延伸，`lbu` 不會。

## 4. PIO 程式 ★★

已驗證的程式庫：`practice/pio/programs.pio`（17 個程式，全部通過 `pio_sim.py` 模擬測試）。

### 4.1 PIO 是什麼（一句話）

CPU 旁邊的小型狀態機（RP2350 有 3 個 PIO 區塊，每個 4 個狀態機），每個區塊的指令記憶體只能放 **32 條指令**，共 9 種指令。資料路徑：

```text
CPU/DMA → TX FIFO(4) → [pull] → OSR → [out] → X/Y/腳位 ... [in] → ISR → [push] → RX FIFO(4) → CPU/DMA
```

| 指令 | 作用 |
|---|---|
| `pull` / `push` | TX FIFO → OSR ／ ISR → RX FIFO（預設 block：沒資料或滿了就等） |
| `out dst, n` | 從 OSR 移出 n 位到 x / y / null / pins / isr / pc |
| `in src, n` | 把 src 的**最低** n 位移進 ISR（src：x / y / null / osr / isr / pins） |
| `mov dst, src` | 複製；`mov dst, ~src` 反相；`mov dst, ::src` 位元反轉 |
| `set dst, v` | 設定 0~31 的常數到 x / y / pins / pindirs |
| `jmp cond, label` | 條件：`!x`、`x--`、`!y`、`y--`、`x!=y`、`pin`、`!osre`（OSR 還沒移完） |
| `wait` / `irq` | 等腳位或 IRQ ／ 設定或等待 IRQ 旗標 |

**PIO 沒有 AND、OR、XOR、加法。** 能用的只有：反相 `~`、位元反轉 `::`、移入/移出 n 個 bit、遞減 `x--`、比較 `x!=y`。所有位元運算都要從這幾招組合出來。

### 題 4-1：寫一個資料轉換用的 PIO 程式

**例：交換高低 16 位元**（需要 IN 左移）

```text
.program swap16
.wrap_target
    pull block
    out x, 16          ; x = 低 16 位（OUT 右移：先出 LSB）
    out y, 16          ; y = 高 16 位
    in  x, 16          ; ISR = 低
    in  y, 16          ; ISR = (低 << 16) | 高   ← IN 左移才會這樣
    push
.wrap
```

**例：數 1 的個數**（示範用遞減來計數，**不能開 autopull**）

```text
.program popcount
.wrap_target
    pull block
    mov x, ~null       ; x = 0xFFFFFFFF
bitloop:
    out y, 1           ; 取出一個 bit
    jmp !y, skip       ; 是 0 就跳過
    jmp x--, skip      ; 是 1 就讓 x 減 1（條件成不成立都會減）
skip:
    jmp !osre, bitloop ; 32 個 bit 還沒取完就繼續
    mov isr, ~x        ; ~(0xFFFFFFFF − n) = n
    push
.wrap
```

**其他已驗證的招式**（完整程式在 `programs.pio`）：

| 目標 | 關鍵指令 | 設定 |
|---|---|---|
| `~v` | `mov isr, ~osr` | 預設 |
| 32 位元反轉 | `mov isr, ::osr` | 預設 |
| `v & 0xF` | `in osr, 4` | IN 左移 |
| `(v >> 4) & 0xF` | `out null, 4` → `in osr, 4` | IN 左移 |
| `v >> 4` | `out null, 4` → `mov isr, osr` | 預設 |
| `v << 4` | `in osr, 28` → `in null, 4` | IN 左移 |
| `v ^ 0xFF` | 拆成高 24 位與低 8 位，低位 `mov x, ~x` 再組回 | IN 左移 |
| `v + 1` | `mov x, ~osr` → `jmp x--` → `mov isr, ~x`（因為 ~(~v−1) = v+1） | 預設 |
| `v − 1` | `mov x, osr` → `jmp x--` → `mov isr, x` | 預設 |
| `a == b ? 1 : 0` | `jmp x!=y` | 預設 |

### 題 4-2：C 端初始化與使用

```c
#include "hardware/pio.h"
#include "programs.pio.h"      // CMake：pico_generate_pio_header(app ${CMAKE_CURRENT_LIST_DIR}/programs.pio)
                               //        target_link_libraries(app pico_stdlib hardware_pio)
PIO pio;
uint sm, offset;
bool ok = pio_claim_free_sm_and_add_program(&swap16_program, &pio, &sm, &offset);
hard_assert(ok);

pio_sm_config c = swap16_program_get_default_config(offset);
sm_config_set_out_shift(&c, true,  false, 32);   // OUT：右移、不 autopull、門檻 32
sm_config_set_in_shift (&c, false, false, 32);   // IN ：左移、不 autopush、門檻 32
pio_sm_init(pio, sm, offset, &c);
pio_sm_set_enabled(pio, sm, true);

for (int i = 0; i < n; i++) {                    // 送一個、收一個
    pio_sm_put_blocking(pio, sm, in[i]);
    out[i] = pio_sm_get_blocking(pio, sm);
}
```

舊版 API 寫法：`uint offset = pio_add_program(pio0, &prog); uint sm = pio_claim_unused_sm(pio0, true);`

### PIO 常見錯誤

| 錯誤 | 結果 | 正解 |
|---|---|---|
| shift 方向設錯 | 位元跑到相反的一端 | IN 左移：新位元進 LSB；IN 右移：新位元從 MSB 進來 |
| 程式用 `out` 卻沒開 autopull，也沒寫 `pull` | 永遠卡住 | 加 `pull block`，或 `sm_config_set_out_shift(&c, true, true, 32)` |
| 開了 autopull 又依賴 `jmp !osre` | 迴圈不會照預期結束 | 迴圈式程式不要開 autopull |
| **CPU 一次 put 太多筆才開始 get** | **死結**：RX FIFO 滿了，SM 停在 push；TX 也滿了，`put_blocking` 永遠等不到 | 送一筆收一筆，或同時開兩個 DMA（題 4-3） |
| 忘了 `pio_sm_set_enabled(..., true)` | 完全沒反應 | — |
| 超過 32 條指令 | `pio_add_program` 失敗 | 用 `.wrap` 取代 `jmp` 回到開頭，可以省一條指令 |

### 題 4-3：用 DMA 餵 PIO（大量資料時）

```c

dma_channel_configure(rx, &cr, dst, &pio->rxf[sm], n, false);

dma_start_channel_mask((1u << tx) | (1u << rx));              // 同時啟動
dma_channel_wait_for_finish_blocking(rx);
dma_channel_unclaim(tx); dma_channel_unclaim(rx);
```

## 5. 雙核心與臨界區 ★★

pico-sdk 的工具（API 已對照官方標頭檔）：

| 工具 | 用途 | API |
|---|---|---|
| `critical_section_t` | 跨核心＋關中斷的鎖，**保護短時間的共享存取** | `critical_section_init` / `_enter_blocking` / `_exit` |
| `spin_lock_t` | 硬體（或軟體）自旋鎖 | `spin_lock_claim_unused` / `spin_lock_instance` / `spin_lock_blocking` / `spin_unlock` |
| `mutex_t` | 可以持有較久的鎖（等待時不會關中斷） | `mutex_init` / `mutex_enter_blocking` / `mutex_exit` |
| `queue_t` | **跨核心、跨中斷安全的佇列**，交換資料首選 | `queue_init` / `queue_add_blocking` / `queue_remove_blocking` / `queue_try_add` / `queue_try_remove` |
| multicore FIFO | 核心之間的硬體 FIFO（RP2350 只有 4 格，SDK 自己也會用） | `multicore_fifo_push_blocking` / `multicore_fifo_pop_blocking` |
| 啟動 core1 | | `multicore_launch_core1(func)` |

### 題 5-1：修正 race condition（對應 demo 的 critical-section）

```c
#include "pico/stdlib.h"
#include "pico/multicore.h"
#include "pico/critical_section.h"

#define ROUNDS 100000
static volatile uint32_t counter;
static critical_section_t cs;

static void worker(void) {
    for (int i = 0; i < ROUNDS; i++) {
        // ……耗時的計算放在鎖「外面」……
        critical_section_enter_blocking(&cs);
        counter++;                               // 臨界區：只有這一行
        critical_section_exit(&cs);
    }
}

static void core1_entry(void) {
    worker();
    multicore_fifo_push_blocking(1);             // 通知 core0：做完了
}

int main(void) {
    stdio_init_all();
    critical_section_init(&cs);                  // 一定要在 launch core1 之前
    multicore_launch_core1(core1_entry);
    worker();
    multicore_fifo_pop_blocking();               // 等 core1 做完
    printf("counter = %lu (expect %d)\n", (unsigned long)counter, 2 * ROUNDS);
    while (true) tight_loop_contents();
}
```

**為什麼 `volatile` 不夠：** `volatile` 只保證每次真的讀寫記憶體，**不保證**「讀、加、寫」三步不被另一顆核心插隊。

### 題 5-2：讓它更快（「鎖要抓得越短越好」）

```c
static void worker_fast(void) {
    uint32_t local = 0;                          // 各算各的，完全不用鎖
    for (int i = 0; i < ROUNDS; i++) {
        // ……計算……
        local++;
    }
    critical_section_enter_blocking(&cs);        // 最後只鎖一次
    counter += local;
    critical_section_exit(&cs);
}
```

速度從快到慢：**各自累加最後合併 ＞ 鎖只包住共享變數 ＞ 鎖包住整段計算**（最後一種等於退回單核心）。

### 題 5-3：core0 負責收發、core1 負責計算

見 [題 2-5](#題-2-5pico-rp2350--micro-ros-的完整骨架) 的完整程式：core0 跑 micro-ROS，subscription callback 把工作丟進 `job_q`；core1 從 `job_q` 拿工作、算完放進 `res_q`；core0 主迴圈從 `res_q` 拿結果發佈。

### 雙核心常見錯誤

1. 鎖或佇列在 `multicore_launch_core1` **之後**才初始化 → core1 可能用到未初始化的鎖。
2. 在臨界區裡 `printf`、`sleep_ms`，或等待另一個鎖 → 很慢，甚至死結。
3. `critical_section` **不可重入**：同一個核心進去兩次就會卡死。
4. 兩顆核心同時 `printf` → 輸出交錯。
5. core1 的堆疊很小（約 2 KB）：大陣列要宣告成 `static` 或全域變數，不要放在 core1 函式的區域變數裡。
6. 在 core1 呼叫 micro-ROS 函式 → 隨機當機。

## 6. DMA（資料搬運引擎）★★

demo 的 transfer engine 和 pico-sdk DMA 的對應：

| demo (`engine.h`) | pico-sdk (`hardware/dma.h`) |
|---|---|
| `engine_claim()` | `dma_claim_unused_channel(true)` |

### 題 6-3：找錯題（demo 的「最常見錯誤」）

```c
// ✗ 有錯的版本
uint32_t src[256], dst[256];
dma_channel_config c = dma_channel_get_default_config(ch);
channel_config_set_transfer_data_size(&c, DMA_SIZE_32);
dma_channel_configure(ch, &c, src, dst, sizeof(src), true);   // 錯 1、錯 2
printf("%u\n", dst[0]);                                        // 錯 3
// 錯 4：沒有設定 write_increment
```

| # | 錯誤 | 後果 | 正解 |
|---|---|---|---|
| 1 | `src`、`dst` 順序顛倒 | 把 dst 的內容蓋到 src | `dma_channel_configure(ch, &c, dst, src, ...)` |
| 2 | 筆數給 `sizeof(src)`（1024 bytes） | 搬了 4 倍的量，寫爆後面的記憶體 | `256`，或 `sizeof(src) / sizeof(src[0])` |
| 3 | 沒有等 DMA 完成就讀 dst | 讀到舊資料 | 先 `dma_channel_wait_for_finish_blocking(ch)` |
| 4 | 預設 `write_increment = false` | 256 筆全部寫到 `dst[0]` | `channel_config_set_write_increment(&c, true)` |

其他常見錯誤：資料寬度和指標型別不符（`uint8_t` 陣列卻用 `DMA_SIZE_32`）、位址沒對齊資料寬度、pattern 用區域變數（函式結束後就不存在，DMA 卻還在讀）、通道用完不 `unclaim`（下次 claim 失敗）、在 DMA 還在跑的時候重新設定同一個通道。

### 題 6-4：讓 CPU 和 DMA 同時工作（重疊）

```c
dma_channel_configure(ch, &c, dst, src, n, true);   // 啟動後立刻返回
do_other_work();                                    // CPU 同時做別的事
dma_channel_wait_for_finish_blocking(ch);           // 要用 dst 之前才等
use(dst);
```

**乒乓緩衝（double buffering）：** 資料從周邊（PIO、UART）進來，或要搬到別處時，處理第 k 塊的同時讓 DMA 搬第 k+1 塊：

```c
#define BLK 256
static uint32_t buf[2][BLK];
dma_channel_configure(ch, &c, buf[0], &src[0], BLK, true);           // 先搬第 0 塊
for (uint32_t k = 0; k < nblk; k++) {
    dma_channel_wait_for_finish_blocking(ch);                         // 第 k 塊到齊
    if (k + 1 < nblk)                                                 // 馬上開始搬下一塊
        dma_channel_configure(ch, &c, buf[(k + 1) & 1], &src[(k + 1) * BLK], BLK, true);
    process(buf[k & 1], BLK);                                         // 同時處理第 k 塊
}
```

> **誠實提醒：** 資料本來就在 RAM、只是要計算時，「先搬再算」反而比直接算慢。DMA 的價值在於**和 CPU 平行**，或從周邊大量搬資料。小量資料（幾十 bytes）用 `memcpy` 通常更快。是否真的變快，用 `time_us_64()` 量了才算。

### 題 6-5（進階）：用 DMA sniffer 以硬體計算 CRC32

RP2350 的 DMA 在搬資料時可以順便算 CRC。設定方式已對照官方範例 `pico-examples/dma/sniff_crc`：

```c
uint32_t crc32_dma(const uint8_t *buf, uint32_t len) {
    static uint8_t dummy;                                  // 寫入目標：固定一個位址
    int ch = dma_claim_unused_channel(true);
    dma_channel_config c = dma_channel_get_default_config(ch);
    channel_config_set_transfer_data_size(&c, DMA_SIZE_8);
    channel_config_set_read_increment(&c, true);
    channel_config_set_write_increment(&c, false);
    channel_config_set_sniff_enable(&c, true);             // 這個通道要被 sniff
    dma_sniffer_set_data_accumulator(0xFFFFFFFFu);         // 初始值
    dma_sniffer_set_output_reverse_enabled(true);          // 讀出時位元反轉
    dma_sniffer_enable(ch, DMA_SNIFF_CTRL_CALC_VALUE_CRC32R, true);   // 輸入位元反轉的 CRC-32（找不到這個常數就寫 0x1）
    dma_channel_configure(ch, &c, &dummy, buf, len, true);
    dma_channel_wait_for_finish_blocking(ch);
    uint32_t crc = ~dma_sniffer_get_data_accumulator();    // 最後取反 = 標準 CRC-32（同 zlib）
    dma_sniffer_disable();
    dma_channel_unclaim(ch);
    return crc;
}
```

**一定要先驗證：** `crc32_dma("123456789", 9)` 必須等於 `0xCBF43926`。不相等就改用軟體版（`practice/c/algos.c` 的 `crc32_table`）。

```python
import numpy as np
from custom_msgs.msg import MnistImage
from numpy.typing import NDArray
from rclpy.node import Node
from rclpy.qos import DurabilityPolicy, HistoryPolicy, QoSProfile, ReliabilityPolicy

from srecruit_host.config import load_config


class P1FeederNode(Node):
    """Feeder node for Problem 1: Single board MNIST."""

    def __init__(self, images: list[NDArray[np.uint8]], images_per_second: float):
        super().__init__("p1_feeder")
        qos = QoSProfile(
            reliability=ReliabilityPolicy.RELIABLE,   # 板子端 init_default 是 RELIABLE，要相容
            history=HistoryPolicy.KEEP_LAST,
            depth=10,
            durability=DurabilityPolicy.VOLATILE,
        )
        self.pub = self.create_publisher(MnistImage, "/mnist_input_a", qos)
        self.msgs = []
        for i, img in enumerate(images):              # 先把 50 張全部轉好
            msg = MnistImage()
            msg.id = i                                # ← 欄位名稱以 interface show 為準
            msg.data = img.flatten().tolist()         # ← numpy 一定要 .tolist()
            self.msgs.append(msg)
        self.idx = 0
        self.timer = self.create_timer(1.0 / images_per_second, self.tick)

    def tick(self):
        if self.pub.get_subscription_count() == 0:    # 板子還沒連上就先不送
            return
        if self.idx >= len(self.msgs):
            self.timer.cancel()
            return
        self.pub.publish(self.msgs[self.idx])
        self.idx += 1


def create_node(images: list[NDArray[np.uint8]]) -> Node:
    images_per_second = load_config().publisher["p1"]
    return P1FeederNode(images, images_per_second)
```

**共用：把頂點序列化成 little-endian 位元組**

```cpp
// 每個頂點 12 bytes：x(4) y(4) z(4)，每個 int32 低位元組在前
static uint8_t bytes[12 * MAX_V];
static size_t serialize(const custom_msgs__msg__QsortVertexArray *in) {
  size_t k = 0;
  for (size_t i = 0; i < in->vertices.size; i++) {
    const auto &v = in->vertices.data[i];
    uint32_t f[3] = {(uint32_t)v.x, (uint32_t)v.y, (uint32_t)v.z};
    for (int j = 0; j < 3; j++) {
      bytes[k++] = f[j]; bytes[k++] = f[j] >> 8; bytes[k++] = f[j] >> 16; bytes[k++] = f[j] >> 24;
    }
  }
  return k;
}
```

> **不要直接 `memcpy` 整個 struct**：如果頂點 struct 裡還有其他欄位（例如 distance）或 padding，位元組就會多出來。逐欄位序列化最保險。

**板子 A：依距離排序**

```cpp
static inline uint64_t dist2(const custom_msgs__msg__QsortVertex &v) {
  int64_t x = v.x, y = v.y, z = v.z;
  return (uint64_t)(x * x) + (uint64_t)(y * y) + (uint64_t)(z * z);  // 不用 sqrt；總和用 uint64 才不會溢位
}

void qsort_callback(const void *msgin) {
  const auto *in = (const custom_msgs__msg__QsortVertexArray *)msgin;
  size_t n = in->vertices.size;
  for (size_t i = 0; i < n; i++) out_buf[i] = in->vertices.data[i];
  for (size_t i = 1; i < n; i++) {                  // 插入排序：穩定，距離相同時保留原順序
    auto key = out_buf[i];
    uint64_t kd = dist2(key);
    size_t j = i;
    while (j > 0 && dist2(out_buf[j - 1]) > kd) { out_buf[j] = out_buf[j - 1]; j--; }
    out_buf[j] = key;
  }
  out_msg.id = in->id;
  out_msg.vertices.size = n;                        // out_msg.vertices.data 已在 setup 指向 out_buf
  rcl_publish(&qsort_pub, &out_msg, NULL);
}
```

> **距離相同時的順序**：judge 若用 Python 的 `sorted()`（穩定排序），就要用穩定排序（插入排序、合併排序）。若全部正確但少數幾筆錯，八成是同距離的順序問題。

```cpp
}
```

**全錯時的檢查清單：**

| 現象 | 可能原因 |
|---|---|
| SHA 全錯 | SHA-0 / SHA-1 弄反（只差 `rol32(t, 1)` 這一行）；digest 每個 word 的位元組順序（試試每 4 bytes 反過來） |
| CRC 全錯 | 序列化的 endianness 或欄位順序；初始值 / 最後取反 |
| 排序大致對、少數錯 | 同距離的順序（穩定性）；平方和溢位 |
| 全部沒收到 | 輸入陣列沒配置記憶體（題 2-2） |

## 8. 考場策略

### 8.1 時間分配（以去年的配分為例）

```text
前 15 分鐘   讀完題目與 README，跑過一次官方流程（燒錄 → agent → judge），確認環境正常
            grep -rn TODO 找出所有要填的地方
接下來       先拿「送分題」：Domain ID、最基本的 callback/feeder → commit + push
            （去年 5 + 15 = 20 分只要基本功能能動）
然後         每題都先做出「正確」，commit + push，再回頭做「速度」
最後 20 分鐘 不再大改，確認 git diff --stat 只動到允許的檔案，最後一次 push
```

### 8.2 原則

1. **先正確、再求快。** 速度分有「正確數門檻」，不正確的話速度再快都是 0 分。
2. **每完成一步就 commit + push。** 去年有「完成時間序」的分數，而且 push 了才會觸發 CI 計分。
3. **只改允許修改的檔案。** 交卷前跑 `git diff --stat` 確認。
4. **卡住超過 15 分鐘就換題**，回頭再做。
5. **每次只改一個地方**，改完馬上測。同時改很多地方，壞掉就不知道是哪裡。
6. **把每次測試的速率、正確數、時間記在紙上**，才知道哪個設定最好。
