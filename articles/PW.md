## 前言

這個網站陪著我，從什麼都不懂的新手一路走到現在。

很難想像，它一開始只是一個單頁式的簡陋網頁，內容少得可憐。<sub>聊勝於無的那種</sub>

跟很多人的個網不同，我的網站沒有用任何框架、模板或建置工具，從頭到尾都是手寫的 HTML、CSS 和 JavaScript。從 2025 年 3 月建立 repo 到現在，將近兩年，累積了四百多次 commit。<sub>其中有一些不是我寫的，後面會講</sub>

這篇就來聊聊這個網站是怎麼長成現在這樣的，還有我一路上踩過的坑。

## 為什麼不用模板

雖然但是，這個網站現在長這樣，完全不在我的計畫裡。

一開始，我只是想做一個網頁來練習前端，所以它理所當然地從第一行就是手寫的。再加上我不太喜歡那些千篇一律的模板，<sub>那挺醜的</sub>所以練習告一段落之後，我決定繼續做下去，也期許自己能做出一些跟別人不一樣的效果和功能。

## 純手刻不是個好主意

我再說一次：純手刻不是個好主意。

這將近兩年、四百多次的更新，每加一個功能都跟坐牢一樣。

早在做完第三個頁面的時候，我就已經開始後悔了。但越做下去，放棄的沉沒成本就越高。每一個功能、每一個設計、每一個頁面、每一次優化，所有細節都得自己一個一個看、一個一個修、一個一個寫。

這也是為什麼直到今天，我的經歷頁都還沒完成。<sub>絕對不是因為我懶(⁠ ⁠╹⁠▽⁠╹⁠ ⁠)</sub>

## 開發過程

回頭翻 commit 紀錄，這個網站大概可以分成這幾個階段：

### 2025.03｜一頁打天下

第一版只有 `index.html` 和 `style.css` 兩個檔案，網頁標題叫 `owo`。

整個網站就是一頁、四張卡片：首頁、關於我、我的 Discord 機器人「一隻笨貓AI」<sub>那時搞出來的破東西ww </sub>、聯絡我。導覽列上的四個連結，也只是跳到同一頁的錨點而已。

至於首頁那張卡片，內容只有一句「歡迎來到這裡 (^⊙ω⊙^)」。<sub>真的是聊勝於無</sub>

### 2025.06 – 08｜拆成多頁

暑假是網站長得最快的時候，光是 2025 年 8 月我就推了七十次 commit。<sub>因為我後來就跑去玩 AI 了:D</sub>

首頁、關於我、技能樹、經歷、友站這幾個頁面都是在這段時間陸續出現的。我也是在這時候加了 GitHub Actions，讓它定期把我的 contribution 圖生成一條貪吃蛇。<sub>嗯...所以所有的提交中也有蠻多是自動更新的</sub>

不過導覽列上的「經歷」只是一顆按鈕，按下去只會跳出「網頁維護中」。而這個提示，一掛就是快一年。

### 2025.09 – 2026.03｜修修補補

這半年沒有新頁面，主要都在修 bug、調樣式，還有跟響應式設計搏鬥（後面會講）。

### 2026.04｜論壇上線

因為開始想寫文章，所以做了「論壇」。  
當然同時也是想把 Hackmd 上的東西改放到自己的個網上，畢竟 Hackmd 對手機的支持以及美術設計都爛死了。

文章用 Markdown 寫，`manifest.json` 記錄每一篇的標題、日期和標籤，`article.js` 讀進來之後再用 marked.js 渲染成 HTML。後來又陸續加上 KaTeX 數學式、highlight.js 程式碼上色和 Mermaid 流程圖，寫教學文終於不用截圖貼公式了。<sub>雖然我原本是希望讓一些簡圖也不用貼的</sub>

第一篇文章是特選心得。<sub>然後那篇到現在都還沒寫完,因為我破防了 嗚嗚嗚qwo</sub>

### 2026.05｜把導覽列抽出來

在這之前，每一頁的導覽列都是直接複製貼上的。要改一個連結，就得把每一頁打開各改一次；漏改一頁，就會出現「這頁有、那頁沒有」的靈異現象。

後來終於受不了，寫了 `common.js`：所有頁面的導覽列都由同一份資料生成，改一次就全站生效。

### 2026.06｜經歷頁時隔一年終於開工

經歷頁終於有了樣子：做成北斗七星，點一下畫面就會一路放大到星座，七個時期對應七顆星，從天樞排到搖光。

### 2026.09｜大重構

把散落在各頁 CSS 裡的顏色、圓角、間距全部收進 `base.css`，變成一組設計變數。現在全站有五百多處 `var(--…)` 都指向同一份設定，想換主題色只要改一行。

同時，星空、點擊漣漪、回到頂端這些特效也整理進了 `fx.js`，順便補上 sitemap 和 SEO 相關的設定。

## 那些踩過的坑

### CSS 對不上

我的天啊，真的跟坐牢一樣。

最一開始我完全沒有做任何管理，每一頁的 CSS 各寫各的，導致前期一天到晚都在找「為什麼這頁的通用設定跟那頁對不上」。

現在回頭看，原因其實很簡單：同一個東西寫了好幾份，改了其中一份，其他份當然不會跟著變，同時也犯了相同樣式不同實現的坑。這也是後來要把導覽列抽成 `common.js`、把設計變數收進 `base.css` 的原因。

### 響應式設計

另一個大坑是響應式設計。

一開始我用硬編碼，每個螢幕尺寸各設一套：螢幕多寬的時候，字多大、間距多少、圖片多寬，全部寫死。說實話，那是個爛主意。尺寸一多就寫不完，而且永遠會有某個尺寸跑版。

現在改成比例化設計，用 `clamp()` 搭配 `vw`，讓尺寸跟著螢幕寬度等比縮放，同時設好上下限：

```css
--navbar-h:  clamp(60px, 4.6vw, 84px);
--sidebar-w: clamp(210px, 18vw, 340px);
--sp-md:     clamp(16px, 2vw, 40px);
```

以第一行為例：導覽列的高度是螢幕寬度的 4.6%，但最矮 60px、最高 84px。一行就能取代好幾個 media query。

### 沒好好用 Git

整理這篇時間線的時候才發現，四百多筆 commit 裡，有 107 筆的訊息都是「Add files via upload」，因為我都是直接在 GitHub 網頁上傳檔案的。所以上面那條時間線，有一大半是靠比對每個月的檔案清單才拼回來的。<sub>雖然我知道 commit message 很重要 但我懶</sub>

另外，還有 179 筆是 GitHub Actions 的貪吃蛇機器人。它幾乎天天準時上工，比我勤勞多了。

## 我最喜歡的功能：泡泡機

到現在，我最喜歡的功能還是友站頁面的泡泡機。它看起來沒什麼，但光是泡泡的飄浮效果，我就搞了半天ww

點一下頭像，就會冒出一堆泡泡往上飄，其中幾顆大泡泡裡裝著友站的頭像，點下去就能直接過去逛。

泡泡的位置是每一幀重新計算的：垂直方向等速往上；水平方向除了往兩側散開，還疊了一個正弦波讓它左右晃；透明度則隨著時間慢慢變淡。

```js
const y = startY - progress * (startY + 20);
const x = startX + scatterX * progress
        + Math.sin(elapsed * frequency) * amplitude;
el.style.opacity = 1 - progress;
```

每顆泡泡的振幅、頻率和飄的時間都是隨機的，所以不會整齊得像在閱兵。另外還有幾個小細節：

- 大泡泡會檢查彼此的距離，太近就重新抽位置（最多試 30 次），避免頭像疊在一起
- 泡泡數量會跟著螢幕寬度調整，手機上 12 顆、桌機上 40 顆
- 友站名單每次都會先洗牌，所以每次飄出來的人都不一樣

現在友站已經有 30 個了，想交換友站的歡迎來找我owo。

## 優化

整個個網的優化陸陸續續做了好幾次，每次都是修好一個地方，又發現另一個地方可以更好。比較大的幾次是：

- **共用的東西只寫一份**：導覽列在 `common.js`、設計變數在 `base.css`、特效在 `fx.js`，全站共用
- **圖片瘦身**：部分圖片換成 WebP，友站頭像和貪吃蛇動畫改成延遲載入，不會一進頁面就全部下載
- **換頁動畫**：用 CSS 的 View Transitions，只要幾行 CSS，換頁時就會淡入淡出
- **SEO**：補上 sitemap 和 robots.txt，每篇文章也會自動設定 canonical 網址和分享預覽資訊 <sub>哈哈你敢信SEO是最近才加的</sub>

對了，網站裡還藏了一些小彩蛋，有興趣的可以自己找找看。
