## 0. 心智模型：30 秒看懂 ROS 2

```text
           topic 名稱：/number          topic 名稱：/double
           型別：std_msgs/msg/Int32     型別：std_msgs/msg/Int32
 [publisher] ─────────────────> [processor] ─────────────────> [judge]
    node          publish        node（同時是            subscribe  node
                                 subscriber 與 publisher）
```

| 名詞 | 白話解釋 | 考試中的例子 |
|---|---|---|
| **node** | 一個參與 ROS 通訊的程式單位（一支程式可以有一個或多個 node） | feeder、judge、板子上的 client |
| **topic** | 有名字的資料通道，**名字要一字不差**才會連上 | `/mnist_input_a`、`/number` |
| **message type** | topic 上資料的格式，兩端**必須同型別** | `std_msgs/msg/Int32`、`custom_msgs/msg/MnistImage` |
| **publisher / subscriber** | 送資料的一方 / 收資料的一方，彼此不需要認識 | feeder 是 publisher，judge 是 subscriber |
| **QoS** | 傳輸品質設定（可靠 / 盡力、佇列深度…），**兩端不相容就收不到** | RELIABLE vs BEST_EFFORT |
| **ROS_DOMAIN_ID** | 「頻道號碼」，**不同號碼彼此完全看不見** | 去年第一小題 (1)，5 分 |
| **service** | 一問一答（request/response） | 查詢設定 |
| **action** | 長時間任務，有進度回報、可取消 | 移動到某位置 |
| **micro-ROS** | 跑在微控制器上的精簡 ROS 2，需要 PC 上的 **agent** 轉接 | ESP32 / Pico 上的 client |

**最重要的一句話：** topic 名稱、型別、QoS、Domain，四個只要有一個不對，就會「程式不報錯，但資料不會過去」。考試一定會考這件事。

## 1. 環境：source、Docker、多終端機、Domain

### 1.1 每開一個新終端機，都要先 source

```bash
source /opt/ros/jazzy/setup.bash      # 考場若是 Humble 就改成 /opt/ros/humble/setup.bash
echo $ROS_DISTRO                      # 印出 jazzy 或 humble 才算成功
```

- 今年 demo 的 Dockerfile 已經把 source 寫進 `~/.bashrc`，所以 `docker exec` 開的終端機會自動 source。
- 如果是自己建的 colcon 工作區，還要再 source 工作區：`source install/setup.bash`。
- 出現 `ros2: command not found`，就是忘了 source。
- 出現 `Package 'xxx' not found`，就是工作區沒 source，或是沒有 build。

### 1.2 在 Windows 上把 demo 環境跑起來（考前練習用）

1. 用**系統管理員身分**開 PowerShell，執行 `wsl --install`，完成後重新開機。
2. 安裝 [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)，安裝時勾選 WSL 2 backend。
3. 開 PowerShell，執行：

```powershell
cd C:\Users\user0409\Downloads\demo\demo
docker build -t srecruit-demo .
docker run --rm -it --name srecruit-demo -v "${PWD}:/demo" -v "C:\Users\user0409\Downloads\demo\exam-prep:/prep" srecruit-demo
```

4. 這樣進到 container 之後：`/demo` 是官方練習，`/prep` 是這份備考資料（裡面的 `practice/` 可以直接執行）。
5. 要開第二、第三個終端機時，另開一個 PowerShell 視窗執行：

```powershell
docker exec -it srecruit-demo bash
```

### 1.3 同時開多個終端機的方法

| 方法 | 操作 |
|---|---|
| VS Code 內建終端機 | `` Ctrl+` `` 開關終端機，`Ctrl+Shift+5` 分割，終端機面板右上角的「+」新增 |
| 另開視窗進同一個 container | `docker exec -it <container名稱> bash` |
| 在背景執行 | 指令後面加 `&`，例如 `python3 publisher.py &`；`jobs` 列出、`kill %1` 結束 |

> 考試時建議固定分工：**終端機 1 = agent / 板子、終端機 2 = 自己的 node、終端機 3 = 觀察用 CLI、終端機 4 = judge**。

### 1.4 Domain 與探索（discovery）相關環境變數

| 變數 | 作用 | 常用指令 |
|---|---|---|
| `ROS_DOMAIN_ID` | 頻道號碼，預設 0（沒設定就是 0），建議範圍 0–101 | `echo $ROS_DOMAIN_ID`、`export ROS_DOMAIN_ID=1` |
| `ROS_LOCALHOST_ONLY` | Humble：設為 1 只在本機通訊 | `export ROS_LOCALHOST_ONLY=1` |
| `ROS_AUTOMATIC_DISCOVERY_RANGE` | Jazzy 的新寫法：`LOCALHOST` / `SUBNET` / `OFF` | `export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` |
| `RMW_IMPLEMENTATION` | 底層 DDS 實作（預設 Fast DDS） | 通常不用動 |

**`export` 只對「目前這個終端機」有效。** 每個終端機的設定都要一致，或是寫進 `~/.bashrc`。

```bash
# 一次檢查目前終端機的 ROS 設定
printenv | grep -E 'ROS|RMW'
```

### 1.5 `ros2 daemon`：CLI 顯示的資訊過時了怎麼辦

`ros2 node list` 這類指令會透過背景的 daemon 快取探索結果。**改過 `ROS_DOMAIN_ID`，或是 node 明明已經關了卻還在列表上時：**

```bash
ros2 daemon stop      # 下次執行 ros2 指令時會自動重新啟動
ros2 node list --no-daemon --spin-time 3     # 不經 daemon，直接探索 3 秒
```

## 2. CLI 速查（考試最常用）

### 2.1 Node

```bash
ros2 node list                       # 列出所有 node
ros2 node info /processor            # 這個 node 訂閱 / 發佈了哪些 topic、提供哪些 service
```

`ros2 node info` 的輸出要看懂：

```text
/processor
  Subscribers:
    /number: std_msgs/msg/Int32        ← 它「收」哪個 topic、什麼型別
  Publishers:
    /double: std_msgs/msg/Int32        ← 它「送」哪個 topic
    /parameter_events: rcl_interfaces/msg/ParameterEvent   ← 系統內建，忽略
    /rosout: rcl_interfaces/msg/Log                        ← 系統內建，忽略
```

### 2.2 Topic

```bash
ros2 topic list                      # 列出所有 topic
ros2 topic list -t                   # 連型別一起列（很好用）
ros2 topic info /number              # 型別、publisher 數、subscriber 數
ros2 topic info /number -v           # 再加上每個端點的 node 名稱與 QoS（查 QoS 不相容必用）
ros2 topic type /number              # 只印型別
ros2 topic find std_msgs/msg/Int32   # 反查：哪些 topic 用這個型別

ros2 topic echo /number              # 持續印出收到的資料（Ctrl-C 結束）
ros2 topic echo /number --once       # 只印一筆就結束
ros2 topic echo /img --no-arr        # 陣列太長時不印陣列內容
ros2 topic echo /img --field id      # 只印某個欄位
ros2 topic hz /number                # 發佈頻率（測吞吐量）
ros2 topic bw /img                   # 頻寬（bytes/s）

ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"      # 送一筆
ros2 topic pub -r 10 /number std_msgs/msg/Int32 "{data: 21}"       # 每秒 10 筆，一直送
ros2 topic pub -t 5 /number std_msgs/msg/Int32 "{data: 21}"        # 送 5 筆就停
ros2 topic pub -w 1 --once /number std_msgs/msg/Int32 "{data: 21}" # 等到至少 1 個訂閱者再送
ros2 topic pub --once --qos-reliability best_effort /number std_msgs/msg/Int32 "{data: 1}"
```

> **重要：** `ros2 topic echo` 會**自動配合** publisher 的 QoS。所以 echo 看得到資料，**不代表**你自己寫的 RELIABLE subscriber 也收得到。這種情況要用 `ros2 topic info -v` 比對 QoS。

### 2.3 Interface（訊息格式）

```bash
ros2 interface show std_msgs/msg/Int32          # 看欄位：int32 data
ros2 interface show custom_msgs/msg/MnistImage  # 考題的自訂訊息，寫程式前一定要先看
ros2 interface proto std_msgs/msg/Int32         # 印出可以直接貼給 topic pub 的 YAML 範本
ros2 interface list | grep custom               # 列出所有自訂型別
ros2 interface package custom_msgs              # 列出某套件的所有型別
```

### 2.4 `topic pub` 的 YAML 寫法

```bash
# 單一欄位
"{data: 21}"
# 多個欄位
"{id: 3, value: 1.5, name: 'abc'}"
# 陣列
"{data: [1, 2, 3, 4]}"
# 巢狀訊息
"{position: {x: 1.0, y: 2.0, z: 0.0}}"
# 訊息陣列（例如頂點陣列）
"{vertices: [{x: 1, y: 2, z: 3}, {x: -1, y: 0, z: 5}]}"
```

不確定怎麼寫時，**先 `ros2 interface proto <型別>` 再改數字**。

### 2.5 Service / Parameter / Run / 其他

```bash
ros2 service list -t                                    # 列出 service 與型別
ros2 service call /set_flag std_srvs/srv/SetBool "{data: true}"
ros2 param list                                         # 所有 node 的參數
ros2 param get /feeder rate
ros2 param set /feeder rate 20.0
ros2 run <套件> <執行檔> --ros-args -p rate:=20.0        # 啟動時給參數
ros2 run <套件> <執行檔> --ros-args -r /old:=/new        # topic 重新命名（remap）
ros2 run <套件> <執行檔> --ros-args -r __node:=my_name   # 改 node 名稱
ros2 pkg list | grep srecruit                           # 找套件
ros2 pkg executables srecruit_host                      # 這個套件有哪些可執行檔
ros2 launch <套件> <launch 檔>
ros2 doctor --report                                    # 環境健檢
```

### 2.6 組合技：只用 CLI 測試一個 node

```text
終端機 A：python3 processor.py                                     ← 被測的 node
終端機 B：ros2 topic echo /double                                  ← 觀察輸出
終端機 C：ros2 topic pub --once /number std_msgs/msg/Int32 "{data: 21}"   ← 餵已知輸入
預期：B 印出 data: 42
```

這就是 demo section2-1 第 5 節教的方法：**`pub` = 臨時 publisher，`echo` = 臨時 subscriber**，不用另外寫測試程式。

## 3. 除錯流程：資料沒過去時

### 3.1 固定的檢查順序（背起來）

```text
① node 在不在？           ros2 node list
② topic 在不在？          ros2 topic list -t
③ 兩端是不是同一個 topic？ ros2 node info <兩端的 node>   ← 名稱差一個字就不同
④ 數量對不對？            ros2 topic info <topic>        ← Publisher count / Subscription count
⑤ QoS 相不相容？          ros2 topic info <topic> -v
⑥ 型別一不一樣？          ros2 topic list -t（同名不同型別會列出兩個型別）
⑦ 真的有資料嗎？          ros2 topic echo / ros2 topic hz
⑧ 以上都對但沒輸出？      問題在 node 內部：沒 spin、callback 例外、欄位填錯、卡在迴圈
```

### 3.2 症狀對照表

| 症狀 | 最可能的原因 | 怎麼確認 | 修法 |
|---|---|---|---|
| `ros2 node list` 看不到某個 node | Domain 不同 / 程式沒在跑 / 板子沒連上 agent | `echo $ROS_DOMAIN_ID`；`ROS_DOMAIN_ID=1 ros2 node list` 換號碼試試 | 統一 Domain ID |
| 看得到 node，但 topic 名稱怪怪的 | topic 打錯字、namespace、相對名稱 | `ros2 node info` | 改成正確的絕對名稱 `/xxx` |
| `Subscription count: 0` | 訂閱端連到別的名字 | `ros2 topic list` 會多一個奇怪的 topic | 改名稱 |
| echo 看得到資料，我的 node 收不到 | QoS 不相容（BEST_EFFORT 發佈 → RELIABLE 訂閱） | `ros2 topic info -v`；Jazzy 會印 `incompatible QoS` 警告 | 訂閱端改 BEST_EFFORT 或發佈端改 RELIABLE |
| `topic list -t` 出現兩種型別 | 同名 topic 用了不同型別 | `ros2 topic list -t` | 統一型別 |
| 前幾筆資料遺失 | publisher 在 discovery 完成前就開始送（VOLATILE） | 第一筆 id 不是 0 | 先等 `get_subscription_count() > 0` 再送 |
| 送太快就掉資料 | 佇列（depth）滿了、板子處理不完 | `ros2 topic hz` 輸入 vs 輸出 | 降速率、加大 depth、改善處理速度 |
| node 在、連線對、有輸入，就是沒輸出 | 沒呼叫 `rclpy.spin`、callback 拋例外、欄位填錯 | 看那個 node 的終端機有沒有 Traceback | 修程式 |
| node 已經關了卻還出現在列表 | daemon 快取過時 | `ros2 daemon stop` | — |
| micro-ROS 板子看不到 | agent 沒開 / 埠號錯 / 鮑率錯 / 板子在 agent 之前啟動 / Domain 錯 | agent 加 `-v6` 看有沒有 session 建立 | 先開 agent 再按板子 reset |

### 3.3 QoS 相容表（一定要會）

**Reliability（可靠性）**

| 發佈端 ↓ ／ 訂閱端 → | RELIABLE | BEST_EFFORT |
|---|---|---|
| **RELIABLE** | ✅ | ✅ |
| **BEST_EFFORT** | ❌ 收不到 | ✅ |

**Durability（持久性）**

| 發佈端 ↓ ／ 訂閱端 → | VOLATILE | TRANSIENT_LOCAL |
|---|---|---|
| **VOLATILE** | ✅ | ❌ 收不到 |
| **TRANSIENT_LOCAL** | ✅ | ✅（晚加入的訂閱者也拿得到最後幾筆） |

口訣：**「訂閱端要求的，不能比發佈端提供的還高」**。

- micro-ROS 的 `rclc_subscription_init_default` / `rclc_publisher_init_default` 都是 **RELIABLE**。
- `_best_effort` 版本則是 BEST_EFFORT。
- `qos_profile_sensor_data`（rclpy）是 BEST_EFFORT、depth 5。

## 4. 用 rclpy 寫 node

完整可執行的範本在 `practice/ros2/`：`feeder_template.py`、`processor_template.py`、`multi_feeder_template.py`、`collector_template.py`。

### 4.1 最小骨架（每支程式都長這樣）

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32


class MyNode(Node):
    def __init__(self):
        super().__init__('my_node')          # node 名稱
        # 在這裡建立 publisher / subscription / timer


def main():
    rclpy.init()                             # 1. 初始化
    node = MyNode()                          # 2. 建立 node
    try:
        rclpy.spin(node)                     # 3. 持續處理 callback（不呼叫就什麼都不會發生）
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()                  # 4. 收尾
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()
```

### 4.2 Publisher + Timer（定時送資料）

```python
self.pub = self.create_publisher(Int32, '/number', 10)       # 型別、topic、QoS（數字 = depth）
self.timer = self.create_timer(0.1, self.tick)               # 每 0.1 秒呼叫 tick（10 Hz）

def tick(self):
    msg = Int32()
    msg.data = 42
    self.pub.publish(msg)
```

- 速率 R 筆/秒 → `create_timer(1.0 / R, ...)`。
- 送完要停：`self.timer.cancel()`。
- 確認有人在收：`self.pub.get_subscription_count()`。

### 4.3 Subscriber

```python
self.sub = self.create_subscription(Int32, '/number', self.on_msg, 10)

def on_msg(self, msg):          # msg 就是收到的訊息物件
    self.get_logger().info(f'got {msg.data}')
```

### 4.4 Processor（收 → 算 → 送）

```python
def on_msg(self, received):
    out = Int32()
    out.data = received.data * 2
    self.pub.publish(out)
```

### 4.5 自訂 QoS

```python
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy, DurabilityPolicy, qos_profile_sensor_data

qos = QoSProfile(
    reliability=ReliabilityPolicy.RELIABLE,      # 或 BEST_EFFORT
    history=HistoryPolicy.KEEP_LAST,             # 或 KEEP_ALL
    depth=10,
    durability=DurabilityPolicy.VOLATILE,        # 或 TRANSIENT_LOCAL
)
self.pub = self.create_publisher(Int32, '/number', qos)
self.sub = self.create_subscription(Int32, '/sensor', self.cb, qos_profile_sensor_data)
```

### 4.6 訊息欄位怎麼填（最常卡住的地方）

先執行 `ros2 interface show <型別>` 看欄位，再對照下表：

| .msg 裡的寫法 | Python 裡的型別 | 填值範例 |
|---|---|---|
| `int32 data` | `int` | `msg.data = 5` |
| `float64 x` | `float` | `msg.x = 1.0` |
| `string name` | `str` | `msg.name = 'abc'` |
| `bool flag` | `bool` | `msg.flag = True` |
| `uint8[] data`（不定長） | `array.array('B')` | `msg.data = img.flatten().tolist()` 或 `array.array('B', img.tobytes())` |
| `uint8[784] data`（固定長） | `numpy.ndarray` (uint8) | `msg.data = img.reshape(-1).astype(np.uint8)` |
| `int32[] values` | `array.array('i')` | `msg.values = [1, 2, 3]` |
| `Point[] points`（訊息陣列） | `list` | `msg.points = [Point(x=1.0, y=2.0, z=0.0), ...]` |
| `builtin_interfaces/Time stamp` | `Time` | `msg.stamp = self.get_clock().now().to_msg()` |

> **最常見的錯誤：** 把 numpy 陣列直接塞給 `uint8[]` 欄位，會出現 `AssertionError: The 'data' field must be a set or sequence ...`。加上 `.tolist()` 就好。`.tolist()` 對不定長和固定長兩種寫法都適用，最保險。

### 4.7 參數（讓速率不用改程式）

```python
self.declare_parameter('rate', 10.0)
rate = self.get_parameter('rate').value
# 啟動時：python3 feeder.py --ros-args -p rate:=30.0   （rclpy.init() 預設就會讀命令列參數）
```

去年是用 `settings.toml` 調速率（`load_config().publisher["p1"]`），今年如果有類似的設定檔，**優先改設定檔，不要改程式**。

### 4.8 Service（以防萬一）

```python
from std_srvs.srv import SetBool

# Server
self.srv = self.create_service(SetBool, '/set_flag', self.handle)
def handle(self, request, response):
    response.success = True
    response.message = f'flag={request.data}'
    return response                                  # 一定要 return response

# Client
self.cli = self.create_client(SetBool, '/set_flag')
self.cli.wait_for_service(timeout_sec=5.0)
future = self.cli.call_async(SetBool.Request(data=True))
rclpy.spin_until_future_complete(self, future)       # 不能在 callback 裡呼叫這行（會卡死）
print(future.result().message)
```

### 4.9 效能注意事項（吞吐量計分時很重要）

1. **不要每筆都 print / log**：終端機輸出很慢，改成每 N 筆印一次。
2. **Python timer 不適合非常高的頻率**：需要 >1000 筆/秒時，改成一個 tick 送一批。
3. **publisher 送太快、對方處理太慢** → 佇列滿了就丟資料。吞吐量的上限是「最慢那一段」，先用 `ros2 topic hz` 量輸入端和輸出端。
4. **計分要求 ≥ N 筆正確**（去年是 50 張中至少 40 張）時，速率要調到「剛好不掉太多」的點：**從低速開始，每次提高一點，記錄正確數與時間，找到最佳值。**
5. callback 裡不要 `time.sleep()`：會卡住整個 node。

## 5. micro-ROS：板子上的 ROS 2

### 5.1 架構

```text
  板子 (client)                    PC                                      PC
 ┌──────────────┐  USB 序列埠   ┌────────────────────┐   DDS (ROS 2)   ┌──────────────┐
 │ micro-ROS    │ ────────────> │ micro_ros_agent    │ ──────────────> │ feeder/judge │
 │ rclc 程式    │ <──────────── │ (每塊板子一個 agent) │ <────────────── │ ros2 CLI     │
 └──────────────┘ /dev/ttyUSB0  └────────────────────┘                 └──────────────┘
```

- 板子本身**不會**直接上 DDS 網路，一定要經過 PC 上的 agent。
- 一塊板子對應一個 agent、一個序列埠。
- 板子的 **Domain ID 是在板子程式裡設定的**（`rcl_init_options_set_domain_id`），**不是**看 PC 的環境變數。PC 端的 judge/feeder 要和它一致。

### 5.2 啟動順序（順序錯就連不上）

```bash
# 1. 燒錄（ESP32 / PlatformIO）
pio run -t upload -e p1 --upload-port /dev/ttyUSB0
# 2. 開 agent（序列埠要和板子一致；-b 是鮑率，必須和板子程式一致；-v6 印詳細 log）
ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyUSB0 -b 115200 -v6
# 3. 按板子的 reset（ESP32 是 EN 鍵；Pico 拔插 USB 或按 RUN）
# 4. 確認
ros2 node list          # 應該看到板子的 node，例如 /ebnn_mnist_client
```

| 板子 | 序列埠名稱 | 燒錄方式 |
|---|---|---|
| ESP32 (NodeMCU-32S) | `/dev/ttyUSB0`、`/dev/ttyUSB1`… | PlatformIO Upload |
| Raspberry Pi Pico / Pico 2 | `/dev/ttyACM0`、`/dev/ttyACM1`… | 按住 BOOTSEL 插 USB → 拖 `.uf2`，或 `picotool load -f xxx.uf2` |

- **序列埠一次只能給一個程式用**：開著 Serial Monitor，agent 就打不開埠。
- 找埠號：`ls /dev/ttyUSB* /dev/ttyACM*`，插拔前後各看一次就知道是哪個。
- `-v6` 的 log 出現 `session established` / `create_participant` 表示連上了。

### 5.3 rclc 程式骨架（板子端，C/C++）

去年 `main.cpp` 已經寫好大部分，**你要會讀、會補**：

```cpp
// ---- 全域 ----
rclc_support_t support;
rclc_executor_t executor;
rcl_allocator_t allocator;
rcl_node_t node;
rcl_publisher_t pub;
rcl_subscription_t sub;
std_msgs__msg__Int32 in_msg, out_msg;

// ---- 收到資料時被呼叫 ----
void sub_callback(const void *msgin) {
  const std_msgs__msg__Int32 *m = (const std_msgs__msg__Int32 *)msgin;
  out_msg.data = m->data * 2;
  rcl_publish(&pub, &out_msg, NULL);
}

// ---- 初始化 ----
allocator = rcl_get_default_allocator();
rcl_init_options_t opts = rcl_get_zero_initialized_init_options();
rcl_init_options_init(&opts, allocator);
rcl_init_options_set_domain_id(&opts, 0);                    // ← Domain ID 在這裡
rclc_support_init_with_options(&support, 0, NULL, &opts, &allocator);
rclc_node_init_default(&node, "my_client", "", &support);
rclc_subscription_init_default(&sub, &node,
    ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Int32), "/number");
rclc_publisher_init_default(&pub, &node,
    ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Int32), "/double");
rclc_executor_init(&executor, &support.context, 1, &allocator);   // ← 1 = handle 數量
rclc_executor_add_subscription(&executor, &sub, &in_msg, &sub_callback, ON_NEW_DATA);

// ---- 主迴圈 ----
while (1) rclc_executor_spin_some(&executor, RCL_MS_TO_NS(10));
```

| API | 重點 |
|---|---|
| `rclc_executor_init(..., N, ...)` | N = subscription + timer + service 的**總數**。多加一個 subscription 卻沒把 N 加 1，`add_subscription` 就會失敗 |
| `ROSIDL_GET_MSG_TYPE_SUPPORT(pkg, msg, Type)` | 自訂訊息：`(custom_msgs, msg, MnistImage)`；C 的型別名稱是 `custom_msgs__msg__MnistImage` |
| `rclc_*_init_default` / `rclc_*_init_best_effort` | RELIABLE / BEST_EFFORT |
| `rcl_publish(&pub, &msg, NULL)` | 回傳 `RCL_RET_OK` 才算成功 |
| `rclc_executor_spin_some(&ex, timeout)` | 處理一輪 callback；timeout 太大會降低反應速度 |
| `rclc_timer_init_default` | Humble 用這個；Jazzy 改用 `rclc_timer_init_default2(&timer, &support, period, cb, true)` |

### 5.4 訊息裡有「不定長陣列」時，一定要先配置記憶體

micro-ROS 不會自動配置記憶體。如果訊息裡有 `uint8[] data` 或 `Vertex[] vertices` 這類**不定長**欄位，訂閱前沒有配置 buffer，收到的資料就會**直接被丟掉，callback 也不會被呼叫**（程式不會報錯）。

```cpp
// 方法 1：手動配置（最直接）
static uint8_t img_buf[784];
in_msg.data.data = img_buf;       // 指向 buffer
in_msg.data.capacity = 784;       // 最多能放幾個元素
in_msg.data.size = 0;             // 目前有幾個（收到時會自動填）

// 方法 2：micro_ros_utilities（巢狀訊息比較方便）
#include <micro_ros_utilities/type_utilities.h>
micro_ros_utilities_memory_conf_t conf = {0};
conf.max_string_capacity = 50;
conf.max_ros2_type_sequence_capacity = 100;   // 訊息陣列（如 Vertex[]）最多幾個
conf.max_basic_type_sequence_capacity = 1024; // 基本型別陣列（如 uint8[]）最多幾個
micro_ros_utilities_create_message_memory(
    ROSIDL_GET_MSG_TYPE_SUPPORT(custom_msgs, msg, QsortVertexArray), &in_msg, conf);
```

- **發佈**含陣列的訊息時，也要讓 `.data` 指向有效 buffer，並設定好 `.size`。
- 固定長度陣列（例如 `uint8[784]`）是直接放在 struct 裡的，**不需要**配置。
- 怎麼知道是哪一種？看 `ros2 interface show` 的輸出：有寫數字 `[784]` 的是固定長，空的 `[]` 是不定長。

### 5.5 板子上不能用 `Serial.print` / `printf` 除錯

micro-ROS 走的就是同一條序列埠。印任何東西都會**破壞通訊封包**，agent 就會斷線。替代方案：

1. **LED**：去年程式附的 `rc_check()`（錯誤時 LED 恆亮並停住）、`rc_check_soft()`（錯誤時快閃 5 下）。
2. **開一個 debug topic**：多建一個 publisher 發 `std_msgs/msg/Int32` 到 `/debug`，PC 端用 `ros2 topic echo /debug` 看。記得 executor 的 handle 數只算 subscription/timer/service，publisher 不用算。

### 5.6 訊息大小與速度

- micro-ROS 序列埠傳輸預設的 MTU 約 512 bytes。超過 MTU 的訊息要靠 **RELIABLE** 串流切片傳送（需要來回確認，比較慢）；**BEST_EFFORT 無法傳送超過 MTU 的訊息**。
- RELIABLE 能傳的最大訊息大約是「MTU × 串流歷史數」，常見預設是 512 × 4 ≈ 2 KB。訊息比這個大就會傳送失敗，而且不會報錯。
- 預設的資源上限也很小，例如 micro_ros_platformio 預設一塊板子只能建 1 個 node，publisher 和 subscription 的數量也有上限。需要更多時要改 colcon meta 設定，再 `clean_microros` 重新編譯。
- 鮑率 115200 時，1 byte 約需 87 µs。784 bytes 的影像光是傳輸就要約 68 ms，大約只能跑到 14 張/秒。**傳輸通常才是瓶頸，不是運算。**
- 可以考慮的加速方向（要看題目允許改哪些檔案）：
  1. 提高鮑率（板子的 `Serial.begin(...)` 和 agent 的 `-b` 要一起改）。
  2. 減少傳輸量：例如影像二值化後 8 個像素打包成 1 byte（784 → 98 bytes），在板子端再解開。
  3. 讓 publisher 的速率剛好跟得上板子的處理速度。
  4. 多板平行處理，輪流分配資料。

### 5.7 常見錯誤對照

| 現象 | 原因 | 處理 |
|---|---|---|
| LED 恆亮（`rc_check` 卡住） | 初始化失敗：agent 沒開、Domain/埠號錯 | 先開 agent，再 reset 板子 |
| LED 一直快閃 | `rc_check_soft` 抓到錯誤，通常是 publish 失敗或 spin 逾時 | 看是哪一行回傳錯誤 |
| `ros2 node list` 看不到板子 | Domain 不同、agent 埠號/鮑率錯、序列埠被占用 | agent 加 `-v6` 看 log |
| 看得到板子 node，但 callback 沒反應 | 不定長陣列沒配置、topic 名稱錯、QoS 不相容、executor handle 數不足 | 照第 3 節的流程查 |
| 編譯時 `custom_msgs/msg/xxx.h: No such file` | 自訂訊息沒有編進 micro-ROS 函式庫 | `pio run --target clean_microros -e <env>` 再 build |
| 上傳失敗 `Permission denied` | 序列埠權限不足 | `sudo usermod -a -G dialout $USER`（要重新登入） |

## 7. 抓蟲練習解答

| 情境 | 只用 CLI 看到的線索 | 原因 | 修法 |
|---|---|---|---|
| 1 | `ros2 node info /processor` 顯示 `Subscribers: /numbr`；`ros2 topic info /number` 的 `Subscription count: 0` | topic 名稱打錯 | 改成 `/number` |
| 2 | `ros2 topic echo /sensor` 有資料，但 `/double` 沒有；`ros2 topic info /sensor -v` 顯示發佈端 `BEST_EFFORT`、訂閱端 `RELIABLE`；node 的終端機出現 `incompatible QoS` 警告 | QoS 不相容 | 訂閱端改 BEST_EFFORT（或發佈端改 RELIABLE） |
| 3 | `ros2 topic list -t` 顯示 `/number [std_msgs/msg/Int32, std_msgs/msg/Int64]`；`/double` 永遠是 14 | 同名 topic 混了兩種型別，processor64 只收到 Int64 那條 | 統一型別 |
| 4 | `ros2 node list` 顯示 `/robot/processor`；topic 變成 `/robot/number`、`/robot/double` | node 有 namespace，又用了相對名稱 `number` | 改用絕對名稱 `/number`，或啟動時 remap |
| 5 | 預設 Domain 的 `ros2 node list` 看不到 `/publisher`；`ROS_DOMAIN_ID=7 ros2 node list` 看得到 | Domain 不同 | 所有終端機用同一個 `ROS_DOMAIN_ID` |
| 6 | `/processor` 在、`/number` 的 `Subscription count: 1`、`/number` 有資料，`/double` 卻沒有任何輸出 | node 沒有 spin，callback 永遠不會執行 | 呼叫 `rclpy.spin(node)` |

**情境 6 的教訓：** 外部看起來一切正常（node 在、連線對、輸入有資料）但沒有輸出，問題就在 node 的程式內部。
